## 盤面の「マスの状態」表現を `std::optional<Piece>` + `ViewDto` から全列挙 `enum` に変更する理由

### 背景
- Model 層 (`Board`) は空マスを `std::optional<Piece>`（Square）で表現していた。
- Controller 層 (`GameController`) は GUI 表示用に `ViewSquare` / `ViewBoardLayout`（ViewDto）を生成して返していた。
- C# GUI から参照するため、Interop 層 (C++/CLI) でさらに `ViewDto` → Managed 型への変換が必要だった。

結果として、C# GUI までのデータ変換が二段になりがちだった：

- Model (`optional`) → Controller (ViewDto)
- Controller (ViewDto) → Interop (Managed)

### 方針
盤面の1マス（Square = マスの状態）を、空=0 かつ「先手=正・後手=負」で表現できる **全列挙 `enum`** に置き換える。

- 空マスは `Square::Empty` として表現する
- 先手/後手の区別は列挙子（および値の符号）に含める
- 空チェック等は `isEmpty()` のような薄いヘルパー関数で統一する

### 期待する効果
- `std::optional` を View/GUI 境界へ持ち出す必要がなくなる
- `ViewSquare { hasPiece, owner, pieceType }` のような「マス状態 DTO」を不要にし、`ViewDto` を排除または大幅に簡素化できる
- C++/CLI 側の変換を単純にできる（最終的に配列コピー中心へ寄せられる）
- デバッグ時に列挙子名として状態を追いやすい（`SenteFu` / `GoteFu` など）

### トレードオフ
- マス状態が `PieceType` と `PlayerSide` の直交表現ではなく、「合成表現」になる
- ただし将棋の駒種は固定で増えないため、全列挙による固定表現は現実的
